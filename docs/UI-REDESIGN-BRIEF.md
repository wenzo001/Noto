# Noto（工作代号 Notera）功能与目标交接说明

给 UI 设计师 · 版本线 0.0.64 · 2026-10-05
所有内容对照真实代码核对过，不是规划稿。

> **这份文档刻意不包含任何关于现有界面的描述**：没有布局、栏数、尺寸、颜色、控件位置、文案排布。
> 现有界面**不构成任何约束**，请当它不存在。
> 这里只写两件事：**这个软件能做到什么**，以及**它必须做到什么**。
> 你需要保留的只有 §2 的产品承诺和 §7 的语义底线 —— 其余全部可以重画。

## 1. 项目目标

### 1.1 定位（原话）

> **Local-first 跨平台个人笔记软件**：数据由用户自己掌控，同步后端是用户自有的 WebDAV 服务器，
> 支持 App 级代理，四端原生体验，数据安全优先。

体验参照系：「**手感接近 Apple Notes，但数据存在用户自己的服务器上**」。

### 1.2 唯一的核心承诺

```
安装 → 打开 → 直接写笔记 → 自动保存 →（配好同步之后才）自动同步
```

三个推论，都是验收线：

- **装完是干净的**：没配账户、或同步被关掉，就不该有任何一轮同步在跑，
  也不该有任何视觉暗示"有东西正在上传"。
- **本机永远说了算**：本地写入即时提交，进程被杀不丢字，网络断了照样写。
  同步坏了不影响"能写笔记"这件事 —— 这是 local-first 的实际含义，不是口号。
- **用户不需要理解同步机制**。底层概念（远端清单、版本号、墓碑、拉取/推送、条件写入、租约）
  **属于内部实现，一律不许出现在界面上**。

### 1.3 决策冲突时的优先级梯子（不可重排）

```
数据安全 > 同步正确性 > 稳定性 > 用户体验 > 原生平台体验 > 性能 > 可维护性 > 新功能
```

它的实际裁决力（已经发生过）：

- "漂亮的原生质感"排第 5，"一个不管用的控制"是第 4 层的问题 → **砍效果，不砍功能**
  （那个透明效果开关被整颗删除，而不是留着但不生效）。
- 数据分歧的最坏结果必须是"**多出一份副本**"，绝不能是"**少掉一段话**"
  → **冲突处理是一等产品场景**，不是角落里的提示条。
- 同优先级冲突时，取更严的一侧。

### 1.4 目标用户

- 自己有一台 WebDAV 服务器、想要 Apple Notes 的手感、但不想要厂商账号的人。
- **内网/企业网用户是明确的设计动因**（含公安网一类环境）：
  典型形态是「内网办公 + 家里/移动双环境」，内网服务器常用自签证书，
  企业会把内网根证书装进系统。
  → 这解释了为什么代理与证书配置必须存在、必须能配得很细、且"跳过校验"这一档必须留着并标风险。
- 期望的记录形态：**日记 / 备忘录 / 记事本** 三种。

### 1.5 平台

| | 计划支持 | 真正在硬件上验证过 |
|---|---|---|
| Windows 10/11 x64 | ✅ | ✅ 所有实测读数来自这里 |
| macOS Apple Silicon | ✅ | ❌ 只出过包，没装过 |
| Android arm64-v8a | ✅ | ❌ APK 打出来了，没真机启动过 |
| iOS / iPadOS | 架构预留 | ❌ 未打包 |

**只有一种语言：简体中文**，没有多语言切换。
品牌名未最终确定（可见层已叫 **Noto**，商标与域名核查未完成）。

### 1.6 明确不做（请别为这些设计界面）

厂商账号体系 · 多人协作与共享 · 服务端搜索 · 版本历史上传（历史只留本地）
· 实时多端光标协同 · 插件系统 · 标签（tag）这一概念**在数据模型里根本不存在**
· 表格的单元格级合并 · PAC 自动代理脚本执行

## 2. 功能清单（能力本身，与界面无关）

### 2.1 写

- **一篇笔记 = 一串块**，不是富文本字符串。块类型：
  正文 · 标题 1/2/3 · 引用 · 代码 · 有序列表 · 无序列表 · 清单项（可勾选）·
  图片 · 附件 · 分隔线。
  数据模型还容得下**表格**，但编辑能力没有（见 §6 状态表）。
- **行内标记**：加粗 / 斜体 / 下划线 / 删除线 / 行内代码 / 高亮（可自定义底色）/ 链接 / 文字大小 / 文字颜色。
  链接只接受 http/https/mailto/tel/页内锚。
- **没有独立的"标题"字段**：标题由正文第一行非空文本派生（截断 80 字）。
  这条决定了任何"新建模板"都不能把模板词放在第一段，否则模板词会变成标题。
- **自动保存**，无需手动保存动作；保存状态必须可辨（进行中/待保存/已保存/失败原因）。
- **粘贴只接纯文本**，换行自动拆成块；外部富文本格式刻意剥掉（保证四端表现一致）。
- 块级操作：重排、缩进 0–8 级、删除单块。
- **快速输入**：符号起手即转型（`#` `>` `-` `1.` `[ ]` 代码围栏等），斜杠呼出指令。
  这套手势是刻意从成熟笔记产品借来的，属于产品期望，重画时请保留"打字即成型"这个性质。
- **字数统计**与块数、摘要都是系统算好的，不靠前端猜。
- **降级为只读**的三种真实情形（都必须能看不能改，且说清为什么）：
  ① 这条笔记的格式版本比本机新；② 这条在"最近删除"里；③ 整个数据库版本比本机新（此时整机只读）。

### 2.2 新建

- 空白新建（落点由系统决定，用户不用选）。
- **模板**：待办清单、会议记录（都是极简结构，进去第一件事就是敲自己的标题）。
- **今天**：一天一篇日记，重复点开会回到当天那篇而不是新建。
  "当天"按本机日历判定；从回收站里翻出来的旧当日笔记不能被误认成"今天这篇"。

### 2.3 组织

- **文件夹**：可建、可改名、可删。
  ⚠️ **"只允许一层"目前只是产品口径，底层并不强制**（见 §8）——这是唯一一条会动摇信息架构的未决项。
- 有一个**默认本**：永远存在、不可改名/删除/移动。"没有文件夹"不是一个真实状态。
- **删除文件夹不会连带删笔记**：里面的笔记移入默认本，子文件夹上提一层。
  这个动作**必须在确认时说清"N 篇笔记将移入默认本"**。
- **置顶**（一行可以有第二个写入者：置顶/移动也会推进版本，不能误报"别处改动了"）。
- **移动到其他文件夹**。
- **列表顺序用户不可改**：置顶优先 + 更新时间倒序（这是产品决定，不是没做）。
- **两级删除**：先"最近删除"，再"彻底删除"。
  - 回收站**没有到期日**，永远不会自动变成彻底删除。
  - 恢复之后必须能立刻接着打字。
  - "彻底删除"目前**不删除服务器上的附件字节**（口径未定，见 §8）——这句文案能承诺什么，取决于那条决定。
- **清除一切数据**（需显式确认，清完仍是一个刚装好的可用状态：默认本还在，需重启）。

### 2.4 查找

- **两个档位同时跑，精准的结果排在前面**：
  - 精准 = 每个查询段连续出现；
  - 模糊 = 每个段的三元分词都出现在**同一篇**里（**不是编辑距离**，编辑距离已明确排除）。
- **中文两个字必须能搜到**，这是实测出来的硬约束不是优化项
  （某条路径对 2 字中文会**静默返回 0 行**，所以必须双路径）。
- 结果带回**高亮片段**（系统生成安全 HTML）。
- 不搜回收站。
- 没有：筛选器、按文件夹搜、日期分面、正则、标签。

### 2.5 附件

- **按内容寻址**：同一张图插两次只存一份对象，跨笔记天然去重。
- **每次读取都复算哈希**：文件坏了会知道，宁可显示"字节缺失"也**绝不用错图**。
- **附件永不阻塞打字**（上传下载完全在正文路径之外）。
- **下载可断点续传**，跨轮次、跨重启继续；**上传不可续传**，中断从零开始。
- 每个附件在每台设备上有两个独立事实：本机字节状况（缺/半/有/坏）× 服务器状况（未知/无/有/坏）。
  界面必须能表达"这个对象此刻在哪一侧缺"，**而不是只给一个笼统的传输进度**。
- **终态失败必须给用户可点的动作**（这是用户明确拍过的口径，不接受"只能看着它坏掉"）：
  - **重试取回**：本机没有 / 服务器被判定没有或坏了 → 撤掉否定结论重新排队；
  - **重新上传本机这份**：本机有好字节、服务器那份被证明坏了 → 强制覆盖。
  三种拒绝各有各的话（没登记过 / 没有可重试的 / 没有可上传的本机副本）。
- 上限与配额：单附件 ≤32 MiB（超了在入口就拒并明说），空文件拒绝，
  一轮最多 4 个文件 / 64 MiB（第一个文件豁免，免得大的永远排不上）。
- **回收是"安全的那一半"**：零引用 + 服务器确认存在 + 本机可用的对象，
  先**挪进隔离区**（30 天可撤销）再真删；删除前还要向服务器再问一次，
  404 才标"没有"，超时/5xx **不下结论**。
  边界：没有同步账户的设备**完全不做回收**；本地编辑删掉一张图**不释放引用**；
  服务器侧的孤儿文件**不回收**。

### 2.6 同步

- **完全 opt-in，配置是唯一权威**；关掉就真的不发请求。
- **一台设备只支持一台服务器**（再加第二台会被拒，并告诉用户先停用现有的）。
- 用户侧只有五种事实要表达（**这是语义要求，不是视觉方案**）：
  `已同步` / `正在同步` / `离线` / `同步失败` / `根本没在同步`。
  最后这一格里"没配置"、"已关闭"、"缺口令"是**三句不同的话**，
  且**"根本没在同步"绝不能表现得像在忙**。
- **不许假装更快**：一轮被预算截断时只能说"还在同步"，不能说"已同步"；
  新设备追平几千条可能要十几分钟，这段时间就得诚实地显示在进行中。
  **默认不要设计百分比进度**——总字节数后端拿不到（进度事件里恒为 0）。
- **别的设备正占着写租约** 是一种正常状态，**不算失败**（改动仍在排队）。
- 服务器能力会被自动探测（首次连接 + 每天），结果必须诚实回显，
  包括最弱那一档：**存在真实的覆盖窗口，请跨设备串行编辑**。
  "没探测过" 与 "探测过但不支持" 是两个不同的事实，不许折成一句。
- 删除也是内容（墓碑永不回收）；重复导入同一份包不会产生重复笔记。
- **绝不静默二选一**，两个方向都一样：
  - 本地删了、对面又把它改回来了 → 也要问；
  - 同一轮里用户已经裁过的分歧不会被反复追问，但对方若又动了，重新问；
  - 两边最终内容一模一样 → **不打扰用户**。
- **两套库指向同一个远端目录** → 停下来，**绝不合并**。
- **服务器疑似丢了很多条记录** → 必须人工确认，不许自动兜底。
- 任何同步/网络错误**都不允许阻塞本地写入**（只有三种情况可以：库版本过新、协议不匹配、记录损坏）。

### 2.7 冲突处理（用户会得到什么）

- 一条冲突必须说清：**是哪条笔记、本机是哪一版、对面是哪一版**，
  并且**对面那一版的正文必须以文字呈现**（"看不见的选择不是选择"；也绝不能用一串哈希代替）。
- 四个动作：两份都留 / 用我这一版 / 用服务器那一版 / 手动合并。
  "都留"产生的副本是一篇**普通笔记**，标题为 `原标题（本地副本）`，可编辑可删除可同步。
- "用服务器那一版"必须**照对面那一版的实际意图**执行（对面是彻底删除，就不能给你留下一行可恢复的回收站记录）。
- 没有"全部用远端覆盖"这种批量动作（刻意不做）。
- 取回对面内容失败时**要说出来，且这条冲突不许消失**。
- ⚠️ 底层有一套块级三方合并，**目前产品里没有启用**。
  所以**千万不要设计"已自动合并，你不用管"这种状态** —— 现在同块分歧必然产生副本 + 一条待处理冲突。

### 2.8 凭据、代理与传输安全

- WebDAV 与代理的口令**从不进数据库、从不进配置文件、从不出现在日志**；
  Windows 上放系统凭据库，其他平台**只活本次进程**（用户明确拍板过）。
  → 由此产生三条必须分别在三个时点说的话：**填之前**（这台机器没有凭据库）、
  **存之后**（退出后要重填）、**重启之后**（请重填，**不许写成"已保存"**）。
  这不是 bug，是选定的口径；界面要把它说圆。
- 口令字段在接口上是**只写**的：读回来只有"有没有/这一轮还在不在/能不能持久"三个位，永不含明文。
  空值语义 = "不改"，不是"清空"。
- 代理是 **App 级**（不碰系统全局）：不用 / 跟随系统 / HTTP / HTTPS / SOCKS5，
  各档可带用户名口令（SOCKS5 支持远端 DNS），支持逐条绕过规则。
- TLS 四种策略：严格（跟随系统信任库）/ 固定证书指纹 / 自带根证书（内网自签场景）/ 不校验。
  **"不校验"只适用于本机与内网，且必须显著告警**；`http://` 明文默认拒绝，仅本机放行并常驻告警。
- 传输安全 ≠ 本地静态加密：这两件事**不许混用说法**（见 §8）。

### 2.9 数据进出

- **导出**：一种格式，系统自有的 ZIP 包（笔记 + 文件夹 + 墓碑 + 附件字节 + 元信息），
  可全库也可按子树；子树包会自标"不完整"。目标位置**永远不覆盖已存在的文件**。
  **没有** Markdown / HTML / PDF / 纯文本导出——要画"导出为 PDF"就是在发明能力。
- **导入自己的包**：合并进现有库 / 只在空库时导入（后者遇到非空库或不完整包会硬拒）。
- **导入外部文件**：Markdown · 纯文本 · Evernote `.enex`（一个 enex 可出 N 篇，含图片与附件）。
  单文件 ≤8 MiB，超了要显式失败不许静默截断；二进制内容当场拒；
  按内容哈希去重（可反复导入不出重）；落在默认本；
  报告：新增 / 重复 / 失败 + 人话提示列表。
  front-matter 里的 `date`、`tags` **会被解析但无处安放**（因为没有标签概念）。
- **备份**：整库单文件快照，自校验（校验不过就不算备份存在）；
- **从备份恢复**：先把当前库自动备份一份，校验哈希一致，**排到下次启动生效**（这是正常结果，不是错误）。
- 备份/恢复**不含**附件字节文件、也**不含**服务器地址与代理配置，**永远不含口令**。

### 2.10 平台能力（功能层面）

- 四端一份产品，差异**只允许经能力位表达**；任何"因为 iPhone 所以…"的特判都被判定为设计失误。
- **能力不具备时，那个功能就不该存在**，而不是留个灰着的开关。
  （本项目历史上每一颗假开关——托盘、全局快捷键、系统钥匙串、透明效果——都被 fake-true 过一次，然后删掉。）
- Windows：原生菜单 · 托盘（关窗不退出、后台继续同步）· 两个全局快捷键 · 系统通知。
  通知**只在两件事上发**：出现待处理冲突、同步失败——不多打扰。
- 移动端：单一入口；后台同步有**诚实预算**（系统给多少轮次就用多少，绝不画"后台实时同步"这种饼）。
  **移动端不承诺 30 秒到达**；对用户的说法是"你打开它的时候，看到的基本已经是最新的"。
- 键盘与鼠标**语义等价**：每个快捷键动作都必须有等价的指点路径；键位本身不跨端强行统一。

## 3. 系统必须能表达的"事实"清单（状态语义，不是界面元素）

这是重画时最容易交付不全的部分。每一条都是真实可达的状态，都需要一个说得清的呈现。

| 领域 | 必须表达的事实 |
|---|---|
| 保存 | 正在保存 / 有改动还没落地 / 已落地 / 保存失败并说明原因 |
| 可写性 | 可写 / 这条只读（格式过新）/ 这条只读（在回收站）/ 整机只读（库过新） |
| 同步是否在跑 | 没在跑（并注明：没配 / 已关 / 缺口令）/ 在跑 / 跑完且成功 / 离线（改动留在本机）/ 失败（并说明为什么 + 能不能重试） |
| 同步进行中 | 被预算截断的长时间追平，也要诚实说"还在进行" |
| 写权 | 另一台设备正持有写租约（正常态，不是错） |
| 服务器 | 支持什么 / 不支持什么 / 还没探测过 / 探测失败（三种不同事实） |
| 附件 | 本机缺 / 本机半 / 本机坏 / 本机有；服务器未知 / 没有 / 有 / 坏了；可撤销的隔离期内 |
| 附件动作 | 可重试取回 / 可重新上传 / 没有可重试的 / 没有可上传的 |
| 冲突 | 是哪条、谁的哪一版、对面正文是什么、取回失败了 |
| 账户 | 口令存不存得住、重启后要不要重填 |
| 传输 | 明文 HTTP 已启用（内网）、跳过证书校验（风险）、代理实际走哪条路 |
| 数据操作 | 导入/导出的明细报告；恢复与清除"重启生效"；空库 vs 只有一个默认本 |
| 查找 | 正在查 / 没有结果（并暗示"两个字也能搜"）/ 查询出错 |

一条已确立的事实优先级：**"本机服务连不上" 高于 "你还没配置同步"**
——在本地核心不可达时说"未配置同步"是转移焦点。

## 4. 硬数字（设计要绕过去的物理边界）

| 项 | 数字 | 对设计的含义 |
|---|---|---|
| 首帧到可打字 | ≤400 ms | 首帧路径上**禁止任何网络等待**（硬规则，不是偏好） |
| 冷启动实测 | 空库 866 ms / 5000 条 984 ms / 20000 条 1322 ms | 快到**不需要为启动设计过场或加载呈现** |
| 桌面同步节奏 | 改动后 2.5 s 去抖 + 25 s 一轮；**空轮 = 1 次请求 / 0 字节** | 静止时几乎零流量 |
| 移动同步节奏 | 900 s（且尚未真机实现） | 不能说"实时" |
| 一轮上限 | 200 次请求 / 8 MiB，超出继续下一轮 | 大库首次追平可能是十几分钟的"进行中" |
| 单附件 | ≤32 MiB | 超了在入口就拒 |
| 附件一轮 | ≤4 个 / 64 MiB；下载窗口 4 MiB | 一批附件会分多轮，中间态是"仍在进行" |
| 导入源文件 | ≤8 MiB | 超了必须显式失败 |
| 搜索 | 查询截断 200 字符，返回 80 条；p50 32 µs / p95 1.4 ms（≥3 字），2 字中文 4.1 ms | 检索不是需要"限流提示"的场景 |
| 标题/摘要 | 截断 200 字符 | 列表里单条文本有天然上限 |
| 口令 | ≤256 个 UTF-16 单元 | 超了是具名错误，**绝不截断** |
| 密钥派生 | argon2id ≈400 ms | **禁止放在任何用户可感知的路径上**（若将来加解锁流程，见 §6） |
| 主包体积 | 281 kB（gzip ≈94 kB）；**门禁已于 2026-10-12 补上**（缺口 G61：`scripts/check-frontend-dist.mjs` 现在有上界，只算 `.js`/`.css`/`.html`，`.map` 不计；实测进包三类 **404 601 B / 上界 512 KiB**） | 新控件若引第三方库，成本已被记为技术债；**包变大从此会被门禁说出来**，改预算要显式改那一行并留新读数 |

## 5. 底线约束（非视觉，但有门禁效力）

这些不是风格规定，是"达不到就算缺陷"的下限：

- 触摸目标 **≥44×44**。
- 对比度：两套主题下**正文与次要文本 ≥7:1（AAA）**、弱化文本 ≥4.5:1、
  强调色/链接/压在强调色上的文字 ≥4.5:1。（数值由自动化门禁实测。）
- 只用**系统字体栈**（含中文回退），不引 webfont（离线可用是硬要求）。
- 用户正文字号可调范围 **0.85–1.6**，必须真作用到渲染字号，放大后**不许出现横向滚动**。
- `prefers-reduced-motion` 下动效时长归零；同步动画降级为**静止指示**。
- 每一个可交互控件都必须有**可读名字**。
- 文本不许被静默裁掉（会被自动化在两个视口 × 六个界面上扫描）。
- 界面文案**不许漏出内部码/键名**；每一条拒绝都必须有名有姓，并且**说清没有丢什么**。
- **不许把两种不同情况折成一句话**；**不许画出没有实现支撑的效果**。
- 每一颗画出来的控制，那一下必须真的落在它自己身上（点击后必须能看到可见的界面反应）。

## 6. 能力状态表：已经能做到 / 已实现但还没给用户 / 还没有

**"已实现但还没开放给用户"那一栏是重画时最划算的地方** —— 底下是真东西，只差一个入口。

| 能力 | 状态 |
|---|---|
| 写、组织、查找、附件、同步、冲突、导出入、备份恢复、代理与 TLS | ✅ 已实现并开放 |
| **备份列表选择器**（后端会返回自校验过的、按时间排序、自动跳过坏档的备份清单） | ⚠️ 已实现，**目前要用户手敲文件路径** |
| **系统文件对话框**（挑导入文件/导出位置） | ⚠️ 已接插件，**目前要用户手敲路径** |
| **把文件拖进来**（核心接口已接受本机路径） | ⚠️ 能力已开，**处理函数没写** |
| **同步详情**（阶段、上次成功时间、待处理任务数、开放冲突数、能否重试） | ⚠️ 后端全都有，**目前只透出了 §2.6 那五种事实** |
| **搜索结果分档标注**（精准/模糊、以及走了哪条检索路径） | ⚠️ 后端已算出，**目前被丢掉了** |
| **偏好跨设备带走**（主题、字号等；后端有作用域化偏好存储，含"设备级刻意不上传"） | ⚠️ 后端有，**目前存在只在本机的本地存储里** |
| **文件夹排序 / 移动文件夹**（带环检测） | ⚠️ 后端有，**没有入口** |
| **笔记与文件夹的颜色**（列已在数据模型和接口里） | ⚠️ 已付费，**没有写入方** |
| **"这条是哪台设备改的"**（设备身份已存） | ⚠️ 已存，**从没显示过**；冲突副本的文档本来就想要设备名 |
| **端到端加密**（AES-256-GCM-SIV、24 个恢复词、密钥轮换、"这台设备没有密钥"的检测、密封传输全部有实现与测试） | ⚠️ **整块能力没有任何开放入口**——这是一个完整的、待设计的流程 |
| **版本历史**（每条笔记每个版本都留在本地，含来源标记） | ⚠️ 只能取某一版的纯文本，**没有列表/diff/回滚**；文档写的保留策略尚未实现 |
| **附件管理器**（本机×服务器账本、隔离区、30 天倒计时、回收字节数） | ⚠️ 数据齐全，**只散落在正文里的附件占位上** |
| **诊断**（完整性自检、启动违例记录、"这个地址会走哪条代理"） | ⚠️ 只有命令行，界面没有 |
| **块级三方合并**（同块分歧自动并、"已自动合并"审计位、标量属性合并） | ❌ 代码有且单测通过，**产品里没接线** |
| **表格块编辑** | ❌ 数据模型容纳，**编辑能力没有**；单元格级合并已明确不做 |
| **标签 / 分面筛选 / 正则搜索** | ❌ 数据模型里没有 |
| **本地静态加密（库文件加密）** | ❌ **未实现，且是待决项**（见 §8）。界面上任何"本地数据已加密"的说法目前都是假的 |
| **口令/生物识别应用锁** | ❌ 没有；能力位声明了但零使用 |
| **多窗口同条笔记编辑** | ❌ 未实现，方案未定（倾向：第二窗口只读） |
| **移动端系统分享入口 / 分享出去** | ❌ 规划里有，未实现 |
| **Markdown/PDF/HTML 导出** | ❌ 没有这种格式 |
| 多账户（一台设备多台服务器） | ❌ 存储层已就绪，**协议层刻意挡住** |

> 提醒：能力位里 `生物识别`、`系统分享`、`文件选择器`、`紧凑工具条`、`安全区`、`拖放`
> 属于"已声明、无人使用"。按 §5 的底线，**在这些被真正接上之前不许画对应控件**。

## 7. 三条判定标准（设计师可以拿它自查）

1. **能不能只看界面就说清"此刻到底有没有在同步，以及为什么没有"** —— 但不能出现任何协议词汇。
2. **最坏情况（分歧、附件缺字节、库版本过新、服务器丢了记录）是不是都有能点下去的动作**，
   而不是一个转圈的圈或一句"操作失败"。
3. **有没有画出不存在的功能** —— 对照 §6 那张表，凡是 ⚠️/❌ 的格子，都要先问工程侧。

一句话概括这个产品：它不是"带云同步的笔记"，而是
"**本机永远说了算，同步只是后台的一扇门**；门可能关着、可能排队、可能坏了，但写字这件事不受影响。"

## 8. 未决事项（这些格子上先别作画）

| 未决的事 | 会影响什么 |
|---|---|
| **文件夹到底允许几层** —— "只允许一层"目前只是口径，底层不强制，对端同步或别的入口漏判就会让子层回来 | **整个组织信息架构（扁平 vs 嵌套）**——这条不定，导航结构画完也是白画 |
| **窗口高度受限时的让位策略未定** —— 组织条目、常驻动作、正文三者在小高度下必须有明确的让位优先级；目前没定（现有做法在很矮的窗口下会把整组内容弄丢，那只是反例，不是约束） | 小窗口 / 笔记本分屏 |
| **回收站要不要到期** —— 现在永不自动清空，加不加保留期设置未决 | "最近删除"能承诺什么 |
| **"彻底删除"删不删服务器上的附件字节** —— 现在不删，这个不对称正是"让用户误以为删干净了"的来源 | 永久删除的文案与后果说明 |
| **本地静态加密（库文件）做不做** —— 三个选项都没选；内网/警务环境常把"落盘必须加密"当验收条件 | 安全类文案能不能说"加密"，以及是否多出解锁流程 |
| **端到端加密要不要开放** —— 能力已建成，入口与流程（恢复词、无密钥设备）完全没设计 | 一整块潜在流程（见 §6） |
| **同一条笔记开两个窗口** —— 倾向第二个只读，未定 | 多窗口形态 |
| **文件夹选择器 64 条硬上限** —— 是去掉上限，还是明说"只显示前 64 个" | 移动/导出的选取场景 |
| **快捷键不可自定义**；`Shift+Delete 永久删除`、命令面板 只存在于规划文档，未实现 | 键盘场景 |
| **品牌名**（Notera / Noto）未定，商标核查未完成 | 图标、启动画面、标题 |
| **macOS 与移动端**从未真机验证（窗口顶部的系统叠加区、移动端软键盘避让目前只是推断） | 跨端一致性 |

另有两处读文档时要当心的地方（**照文档描述去画会画错**）：

- 存在两套互相冲突的快捷键表（原生菜单那套与应用内那套），运行时以哪套为准未锁定。
- `docs/CONFLICT-RESOLUTION.md` 的冲突处置流程图里第 ③ 步"块级自动合并（用户不感知）"
  **在库里从来没有为真过**，文档自己也已把这一格标注为缺口 G15；
  同样地，`docs/DATA-MODEL.md` 已明确回收站**没有到期日**（那条"30 天"是附件字节的隔离期，不是笔记的）。
  这两格文档已经改对了，但速读的人容易按旧流程图去画"无感合并"和"到期自动清空"。
