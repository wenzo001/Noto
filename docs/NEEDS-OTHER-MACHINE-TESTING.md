## D25（2026-10-19 新增，第一百五十三批）：**中文标题排序按码位序，要不要变成按拼音序**

- 事实：`ORDER BY n.title COLLATE NOCASE` 是 SQLite 给的顺序 ⇒ **ASCII 在前、中文按码位**。
  对英文与数字标题没问题；对中文标题，"张三 / 李四 / 王五"排出来的先后**不是拼音序**，
  用户看到的就是"没规律"。（标签那一族我们**钉了拼音** —— `zh-Hans-CN`，任务 #11；两处口径不一致是事实，不是疏漏的复制。）
- 为什么现在这样：要拼音序就得引 ICU 类 collation 或自带一份汉字→拼音表。
  **这两条都要往包里加东西**，而本项目对安装包体积有一条硬门（`collect-release-assets` 的上界 + 用户原话"安装包有点大"）。
  现在这一版是**零成本、确定性、跨平台一致**（同一份库在任何机器上排出来一样）。
- 候选：**A** 保持码位序（推荐；标题排序主要给英文/数字/文件名用，中文用户靠搜索而不是靠翻列表）；
  **B** 自带一份常用汉字拼音表（约几十 KB 起，且要维护多音字）；**C** 引 ICU（体积代价最大，四端行为还要各验）。
- 不拍也不阻塞：这一格红了不会挡住 1.0，但**标题排序对中文用户是不是"够用"**只有真机上的他能判断，
  所以留在这里。要验的形状：建 5 篇中文标题（张 / 李 / 王 / 陈 / 赵），选「标题 A→Z」，看读起来像不像排的。
