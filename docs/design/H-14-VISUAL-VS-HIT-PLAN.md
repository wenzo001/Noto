## 1. 工具条图标（§1.4：32；实测 44）
- 今天：`.tb__btn { min-width: var(--touch); min-height: var(--touch) }`（`ToolbarItem.vue:271-274` 与
  `EditorToolbar.vue:377-380` **两处各写一遍**），外面那格 `.tb__cell` 因此被撑到 44×44；图标本体 `.tb__ink` 在里面。
- 目标：可见盒 32×32（`height: var(--h-icon)` / `width: var(--h-icon)`），**命中区仍 44** ——
  命中区交给 `.tb__cell`（它本来就在按钮外面），靠 `min-width/min-height: var(--touch)` + `align-items:center` 撑住，
  按钮自己 `padding: 0` 且不再声明 44。
- 会被踩住：腿 ⑰ 族（全应用 44pt 通扫，它量的是"那颗控件自己的 rect"还是"命中的那一层"要逐条核）、
  腿 65（按下那一格的逐控件通扫）、腿 70（§3.4 工具条条位，含 tab/图标高）。**这三处都要先把尺子改成"命中层 ≥44 且可见层 = 32"两条各自判**。
- ⚠ 两处 `.tb__btn` 声明必须一起改，否则桌面与移动的工具条会长得不一样（§「一份界面服务两端」）。

## 2. 侧栏文件夹行（§1.4：34；实测 44）
- 今天：`.tree__row { min-height: var(--touch) }`（`FolderTree.vue:209`）+ 里面的 `.tree__name { min-height: var(--touch) }`
  同一件事写了**两遍** ⇒ 那一颗圆角胶囊自己就是 44 高，视觉与命中完全绑在一起。
- 目标：`.tree__name`（那颗带 `--r-row` 圆角、hover 底色的可见胶囊）= `height: var(--h-row)` 34；
  `.tree__row` 保留 `min-height: var(--touch)` 当命中层（它已经是对 `.tree__tools` 定位的父级，不改结构）。
  长名字两行的那一档（§5「不许硬截」）不能被 34 顶掉 —— 所以是 `min-height: var(--h-row)`，两行时允许撑高。
- 会被踩住：腿 ⑰（整行命中 ≥44 那条，本来判的是 `.tree__row`，改完仍是 44 ⇒ **不用动**）、
  腿 ㊻/㉑ 族的长文本折行、腿 39 族（小色点与 hover 工具层的垂直居中）。

## 3. 输入框（§1.4：36；实测 45）
- 今天：`.search__input { min-height: 44px; padding: 8px 8px }` ⇒ 框子被触摸下限顶着，45 高。

## 5. 分组标题行（§1.4：24；实测 16）—— 这一格撞的不是 §5，是 §1.5
- §1.5 给分组标题的是 **11/16**（字号/行高），§1.4 给"分组标题行"的是 **24**。两者能同时成立：`16 + 4 + 4 = 24`，
  而那 4px 正好在 §1.2 的网格上（`--sp-1`）。所以"补 `padding-block: var(--sp-1)`"是**唯一同时满足两节**的读法。
- 这一格**不需要裁决**（我第三十六批里说"要裁决"是把两条读法当成了互斥，算错了算术）。但它是产品改动，
  要连着 §1.5 那条腿（正文/分组标题的排版读数）一起看，且和上面几格同属"要整跑"的那一批。
