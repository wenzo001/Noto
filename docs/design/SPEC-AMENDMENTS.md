## A1 · §6「明确不做」· 标签（tag）

- **规范原文那一格**：`标签（tag）（数据模型里根本不存在）`。
- **现在的口径（改口）**：归类语义由笔记 / 文件夹的**单值 `color`** 承担，界面里那颗侧栏小色点就是它的可见形态；
  **仍然不做**的是 tag 数据结构本身 —— 没有多值标签、没有标签表、没有标签管理入口。
- **依据**：2026-10-09 拍板"笔记颜色当标签"（色点落在 0.0.103 / 0.0.108）；2026-10-13 D9 选 A
  （`docs/NEEDS-OTHER-MACHINE-TESTING.md` §D 那一行）。
- **边界（还没拍板的）**：**按颜色检索没有做**，也不许顺手做 —— 它同时撞 §3.3「没有筛选器 / 没有分面」，
  要做得再拍一次，并连那半句一起改口。
- **机器证人**：
  - `apps/desktop/src/negativePromises.spec.ts` › `§6 标签那一格（改口后）…` 四面（schema 表名 / schema 列名 /
    Rust 与前端 DTO 字段 / 控件名 / 文案），10 把变异刀逐条见血；撞名的 `unknown_enml_tags`（ENEX 的 ENML 元素名）
    与 `version-now-tag`（版本历史记号）各有"真在场且被放过"的反向自检。
  - `scripts/verify-layout.mjs` 腿 53：笔记颜色那一半的渲染与写入路径。

## A2 · §3.5「胶囊内左右 6px」的横向读法（解释性裁定，原文未改）

- **原文**：`底部胶囊栏：左右各 12px（安全区内），胶囊内左右 6px、上下 6px`。
- **裁定（2026-10-13 D8 选 A：维持居中）**：横向钉的是**声明值** `padding-inline: 6px` 加上"栏 64 = 描边×2 + padding×2 + tab 52"
  这条恒等式；tab 排布继续 `justify-content: center`，实测左右间隙 35px 是居中的结果，不算违规。
- **上下那半句**早就用"看得见的 6px"钉住（`padding 5 + 描边 1`），三个数同时成立。
- **机器证人**：`scripts/verify-layout.mjs` 腿 ㉕ 的三条 padding 判据。
